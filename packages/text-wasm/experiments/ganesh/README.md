# Ganesh WebGL flower experiment

This is an independent, disabled-by-default experiment. It replays the existing portable SkPicture on a Ganesh WebGL2 surface. Native layout, exact asset closure, per-grapheme texture coordinates, material recording, Lua animation, backgrounds and transparent publication remain in use. It does **not** substitute the incomplete whole-string SDF shader. GPU output currently returns RGBA through readback; direct GPU publication and Worker/OffscreenCanvas integration are not implemented here.

The production SDK, CMake, bridge, renderer and dist are untouched. All copied vendor source, dependency builds, WASM and captured images go into `.local/qa/wasm-gpu-next/`; this directory contains only reviewable experiment code and compact evidence.

## Result and limits

On the real Apple M4 Pro ANGLE Metal GPU, four 1920 × 1080 fixtures used Arial/PingFang SC and `灵感花开`: flower03, flower38, flower03 + tile + Lua letter animation, flower38 + nine-slice + Lua letter animation. Seven times per fixture included `.2 → .8 → 1.3 → 2.6 → 4.8 → .2` seconds. The experimental build's CPU branch matched the frozen production CPU baseline in all 28 raw RGBA comparisons. GPU origin/extent and control geometry matched; backward seeks were deterministic, including the two animated fixtures. The 112 real GPU target allocations equal four fixtures × (7 samples + 20 timing frames + 1 display frame).

**GPU pixels do not match the validated CPU output. This backend must remain experimental.** Fully opaque static flower38 RGB differs by at most 2, but its soft-shadow alpha differs by up to 18; animated nine-slice/flower38 also has local texture/border differences up to 60 in visible composited RGB at .8 seconds. The pictures preserve visible materials, backgrounds and animation, but the soft shadow shows changed edge coverage. No no-quality-loss claim is made.

The final isolated warmed measurement alternated CPU/GPU ordering, discarded five warmup frames, then measured 15 fresh times per fixture; this includes GPU RGBA readback. It is not editor playback FPS.

| Recipe | CPU mean ms | GPU mean ms | GPU p95 ms |
| --- | ---: | ---: | ---: |
| flower03 | 40.73 | 10.19 | 14.10 |
| flower38 | 29.02 | 10.43 | 15.70 |
| flower03 + tile + letter | 24.83 | 9.75 | 11.30 |
| flower38 + nine-slice + letter | 105.48 | 16.91 | 22.60 |

`evidence.json` includes baseline/experimental WASM hashes, alpha/visible RGB metrics, exact CPU control checks, GPU seek checks, and final uncontended timings. Raw `changed`/`over1` are channel-byte counts; `visible.changedPixels` counts pixels in the union of nonzero alpha. Black/white compositing metrics use float RGB before final 8-bit quantization, so tiny nonzero changes need not be visible. The >1 differences above are real.

## Reproduce

Use the pinned toolchain installed by `packages/text-wasm/scripts/setup.mjs` and the CPU SIMD GN arguments generated by `packages/text-wasm/scripts/build.mjs`. The ordinary package should already be built so its dist and vendored source correspond. The experiment does not download dependencies itself.

From the workspace root:

```sh
node packages/text-wasm/experiments/ganesh/build.mjs
VIDEOCUT_GPU_EXPERIMENT_PORT=63808 node packages/text-wasm/experiments/ganesh/serve.mjs > .local/qa/wasm-gpu-next/server.log 2>&1
```

Keep the server running; in another terminal:

```sh
VIDEOCUT_GPU_MODE=1 node packages/text-wasm/experiments/ganesh/run.mjs
VIDEOCUT_GPU_MODE=1 VIDEOCUT_GPU_TIMING_ONLY=1 node packages/text-wasm/experiments/ganesh/run.mjs
```

The fixture opens its own private headless Chrome via the existing backend helper; it never attaches to the user's browser/editor. JSON goes to `report.json`; .8-second images go to `artifacts/mode1-*-{cpu,gpu,diff8}.png`. `diff8` is premultiplied RGB on black amplified eight times. Canvas PNGs may normalize hidden RGB at alpha zero; use raw JSON for byte comparisons. `VIDEOCUT_GPU_REQUIRE_EXACT=1` makes a non-exact quality report exit with failure. Runtime/setup errors exit with failure regardless. Timing-only runs set quality fields to null.

The recorded run used the paired frozen baseline in `.local/qa/wasm-native-next/baseline/` (WASM SHA in `evidence.json`). To repeat that snapshot locally, set `VIDEOCUT_GPU_BASELINE=.local/qa/wasm-native-next/baseline` for the build; the optional three frozen C++ material/publication files are also applied to the independent source copy. Without this option, the current package's dist/source pair is the baseline. A different OS/font/backend or package snapshot may produce different values; CPU build equivalence is checked in every quality run.

## Evaluated candidates

`?mode=1`: original Ganesh, no requested MSAA; closest tested variant.
`?mode=2`: requested 4-sample MSAA; enlarged AA/material errors, rejected.
`?mode=3`: requested 8-sample MSAA; available for diagnosis, not evaluated.
`?mode=4`: disable automatic distance fields, raise glyph path threshold, disable tessellation; enlarged errors, rejected.
`?mode=5`: disable automatic distance fields, raise glyph path threshold; enlarged errors, rejected.

Software path-coverage candidate:

```sh
node packages/text-wasm/experiments/ganesh/hybrid-build.mjs
VIDEOCUT_GPU_MODE=6 node packages/text-wasm/experiments/ganesh/run.mjs
```

This compiles only an isolated `GrRecordingContext.cpp` overlay and replaces its member in the independent Skia archive. Shared Skia source is unchanged; the original archive is saved in `skia-overlay/libskia-native-paths.a`. Mode 6 requests software path coverage with GPU material shading/composition and keeps the original glyph-as-path boundary. All 28 output hashes were identical to the original Ganesh candidate, so it did not improve the remaining filter/texture/blend discrepancy. The build script restores the original object when rebuilding Ganesh.

Current future work is matching Gaussian coverage/texture sampling semantics, directly publishing the GPU surface to the compositor, bounded GPU lifetimes/device-loss recovery, and Worker context integration. Tested material structure does not imply support or quality acceptance for every untested gradient, font, 3D/external component or encoded export.
