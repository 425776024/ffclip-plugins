# Browser render pipeline

`plan.mjs` evaluates the internal version-1 editing projection at integer 120,000 Hz ticks. It samples transform and LUT automation, maps retimed source time, and expands transition handles. It does not serialize projects; native Project Format 1 remains the persistence boundary.

`renderer.ts` consumes the plan through `MediaEngine` readers and the shared text runtime in `text.ts`. Video, image, ordinary text and the six admitted text recipes become inputs to the same compositor. Preview hit bounds are derived from the same affine geometry as the pixels. Preview quality is independent of project/export dimensions.

`gpu.mjs` owns one adapter/device and compiled pipeline cache per execution context. Composition text players borrow that device. GPU devices are not transferable across workers: the preview worker, export worker and UI poster context each own their context. Input texture identity includes source URL/version, actual decoded PTS and dimensions. Unchanged image/text inputs and transform-only edits skip upload. Live textures have a 512 MiB budget; unused layer textures, buffers and decoder leases are released. Large radii use bounded separable passes. The current compositor is 8-bit SDR; this is not an HDR or native Metal backend.

`worker.ts` keeps a frozen project snapshot for export. Preview requests use generations and abort signals: a superseded decode cannot commit a new frame or replace selection geometry. Normal playback coalesces pending frames without continuously restarting its decoder. GPU errors are explicit; device loss rejects the frame. A new renderer acquires a replacement device.

`export.ts` probes browser encoder capabilities and selects one of three paths:

The browser path has no FFmpeg/FFprobe requirement. A job advertises the optional local encoder only after a bounded capability check succeeds. Nothing downloads or bundles a codec binary. With no local encoder and no browser AAC encoder, MP4 export suggests WebM.

- `browser`: WebCodecs video/audio and Mediabunny muxing; seekable compressed chunks go to Node.
- `video-with-pcm`: browser video encoding, the same bounded audio mixer as preview, and optional locally installed FFmpeg for audio encoding/muxing.
- `frames-with-pcm`: the same composited RGBA frames and mixer PCM go to the local encoder with per-chunk acknowledgements and backpressure.

The Node service first freezes and claims the project, then accepts a single encoding configuration. Video, audio and compressed file writes have separate ordered counters. Cancellation stops the worker and server job; incomplete files are removed by the server. The browser page remains required while rendering. `preferredEncoding` supports explicit integration testing without changing the default `auto` selection.

HTML export prepares up to two exact successor screenshots while the current frame is composited and encoded. The service has two independent Chromium capture lanes; each page serializes its own seek/capture and retains the original authored viewport/alpha. The browser reserves full RGBA dimensions against a 64 MiB lookahead limit; consumed, obsolete and cancelled bitmaps are released. Future capture errors surface when their exact frame is consumed. Clip changes and transition/retime samples use the same scene plan as foreground rendering. All three encoding paths share this preparation; `htmlPrefetch: false` provides a sequential diagnostic comparison. Preview retains its foreground seek/cancellation behavior.

The service retains at most eight isolated HTML pages. Eviction closes the old target and reuses its context with a fresh document/global scope, avoiding repeated `Target.createBrowserContext` storage-partition setup during edits. A CDP timeout or disconnection invalidates every pending command on that transport. The renderer retires its owned Chromium process and retries the exact requested frame once; simultaneous lane failures share one replacement. Authored script errors and cancelled requests do not trigger retries. Queued cancellations are checked before page allocation, and shutdown rejects stalled commands before draining queues. See [timeout recovery evidence](../../docs/html-render-recovery.md).

Export also enables the existing two-worker native flower-text pool, preparing at most six successor requests under its 64 MiB RGBA cache limit. Only the admitted non-external flower-style-03/38 recipes use these workers; other templates keep their reference path. Exact RGBA, extent, layout, style, text and source time are retained. GPU composition and encoder submission stay ordered and respect encoder/writer backpressure, while successor text rasterization runs concurrently. Predictions stop at project end, cancellation disposes the workers, and unavailable worker transport falls back to the reference renderer. Native input errors still fail the export. `textWorkers: false` selects the sequential diagnostic path.

`audio-encoder.ts` measures AAC encoder priming with a short deterministic PCM marker and the actual browser encoder/decoder configuration, rather than assuming an operating-system-specific delay. Encoded packets retain decoder priming with negative timestamps; the MP4 muxer's public packet API writes an edit list and a shortened final packet. Calibration failure uses the optional local encoder in automatic mode, or rejects with a WebM suggestion. Opus timing uses the pre-skip value from its actual OpusHead. WebM has millisecond timestamp precision, and Mediabunny 1.61.0 does not expose DiscardPadding; a final compressed frame can still decode to extra tail samples. This is not sample-exact gapless WebM. AAC decoders that ignore the edit-list endpoint can also expose the final partial packet's padding in raw PCM extraction. Neither limitation shifts interior events.

`/tests/browser-audio-sync.html` checks the real browser AAC calibration and writes a three-second, 90-frame fixture with five non-periodic audio markers for independent PTS/cross-correlation inspection. Export uses no FFmpeg postprocessing.

Safari's AAC encoder returns an ES descriptor around its AudioSpecificConfig; `aac-config.mjs` unwraps the bounded descriptor for both calibration and MP4 muxing. Safari AAC also receives a 4096-sample silence guard before authored audio, removed together with measured encoder priming by the edit list, preserving transients at source sample zero. Safari AVC uses `realtime` latency to avoid the Safari 27 quality-encoder queue hang ([upstream report](https://github.com/Vanilagy/mediabunny/issues/541)). Export checks the actual encoded packet count after finalization and rejects missing frames. Other browsers and WebM keep quality latency.

Canvas2D supports basic media/text transforms and blending when WebGPU is absent; complex templates, effect passes and transitions fail explicitly. Four transition formulas, Gaussian radius/sigma semantics and the 33³ look curves follow the desktop contracts. Glow is an SDR approximation of the native Core Image bloom implementation; parameter compatibility is not native pixel equivalence.

Run pure geometry/plan checks with `node --test tests/render-plan.test.mjs`. For real browser coverage, start the API and Vite, run `node tests/render-report-server.mjs`, and open `/tests/browser-render.html?fixtures=<fixture-directory>`. The matrix requires `timecode.mp4`, `stereo.wav` (opposite-polarity channels), `still.png`, and a writable `render-results` child directory. It compares decoded exports against exact-PTS compositor readbacks, exercises all three encoding paths, checks stale-frame cancellation and input uploads, and injects GPU loss. This small-frame matrix does not establish long-form or 4K performance.
