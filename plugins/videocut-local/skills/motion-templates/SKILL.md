---
name: motion-templates
description: Create editable PAGX animation templates for VideoCut, author conversion-ready HTML/CSS/GSAP using the official PAGX guidance, and combine graphics with media on an existing timeline. HTML inputs default to PAGX conversion and fall back to HTML when conversion is unsupported. Also supports native flower text recipes.
---

Use [video-editing](../video-editing/SKILL.md) for sessions, media, preview and export. Read the current session before changing its timeline. Keep videos, images, audio and captions on ordinary tracks.

Call `list_motion_templates` first. It returns native PAGX template IDs, the renderer/converter capabilities, HTML fallback, and flower text components. PAGX is the default animation representation:

- For a built-in design, call `add_pagx_clip` with `id`, `templateId`, optional `locale: "zh" | "en"`, and placement fields. The animation library contains only these native PAGX templates: eight full-frame designs and two transparent overlays. HTML remains an authoring/import path through the tools, with automatic conversion and fallback.
- For described designs authored in HTML, follow the bundled **official [PAGX Skill](../pagx/SKILL.md)** and read [its HTML authoring advice](../pagx/references/authoring-html.md), then [VideoCut's conversion-ready HTML contract](references/html-clip.md). These references have different scope: official guidance describes upstream behavior; the VideoCut contract states the capabilities actually tested in this runtime. Do not assume upstream static capture support means deterministic animation support here.
- Submit HTML through `add_html_clip`, which defaults to PAGX conversion and returns `conversion.renderer`, `fallback`, `reason` and `warnings`. On conversion failure the tool adds the original HTML clip, as requested by the user. Explain this fallback; do not call it GPU/PAGX rendering. `renderer:"html"` is an explicit HTML choice. Keep the original authored file when one exists.
- For precise native geometry, editing a `.pagx`, or designs that do not map cleanly from HTML, author native PAGX using the official XML guide/patterns and [the VideoCut PAGX bridge](references/pagx.md). Call `add_pagx_clip` with inline `pagx` or authorized `.pagx` `path`.

Clicking either clip opens editable content fields. PAGX exposes semantic text, font family, size, faux bold/italic, colors, shape sizes, positions, corner radius, opacity and supported blur values. Values controlled by internal channels are marked read-only. Give native `Layer` elements meaningful `name` attributes. Keep user-facing labels free of XML, JavaScript and internal IDs. New content follows the requested language; changing the UI language must not translate existing project content.

`set_pagx_clip` and `set_html_clip` replace the corresponding source while preserving source range and placement. Raw `edit_timeline` HTML commands deliberately keep HTML and do not perform asynchronous conversion; use `add_html_clip` or `convert_html_to_pagx` before batched PAGX insertion when conversion is desired. One second is 120000 ticks; trim/split/move command seconds fields retain their documented units. Do not replace a PAGX item with stale HTML after the user edited its parsed properties.

For flower text use `add_text` and `nativeComposition` from `list_motion_templates`. Added backdrop/animation components are supported only with `flower-style-03` or `flower-style-38`; other bases retain their original graph. Do not invent unshipped components. Preserve native typography by default; override with `template.style.color/fontSize`, and position/scale with shared visual controls.

Validate entrance, middle, exit and backward seek in the real VideoCut preview. Review Chinese/Latin fonts, icons, gradient extent, strokes and transparency. Conversion warnings and API success do not establish visual fidelity. Inspect decoded MP4/WebM output when claiming export quality. Save editable PAGX/HTML projects with `save_project` (`.vcutweb`); the native `.vcut` bridge does not store these graphic clips. Conversion and HTML fallback need Chromium; PAGX playback/export uses the WASM renderer and VideoCut encoder without per-frame browser screenshots or a PAG Enterprise SDK.
